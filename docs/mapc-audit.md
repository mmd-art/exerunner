## First package: manual saves and temporary keep-awake

The new **game card → Save backups…** flow uses native Finder panels. Pick one specific save folder and a separate export folder. It never guesses save locations or scans the whole home directory. A plain snapshot contains `manifest.json` and `data/`; file SHA-256 hashes, item identity and format are checked. Only complete manifests are accepted. Export does not change source saves.

Restore selects the target explicitly, previews the replacement count, asks for confirmation, and requires a separate verified safety snapshot before any writes. Existing extra files are retained. Case/Unicode path aliases, symlinks (including ancestors), malformed/foreign manifests, executable files and excessive size/entry counts are rejected. Size limit is 256 MiB, entry limit 10,000, recursion limit 40. A final inventory must match the expected overlay. An interrupted/failed restore retains the old files in its safety snapshot with a local recovery journal; success is not claimed on a partial write. Normal app termination waits for active restore jobs. Failed exports without a final manifest are incomplete and are never offered as valid backups; the feature does not prune user-chosen backup folders.

The environment must be idle. The same cross-process lease used by ExeRunner process creation blocks cooperating launches during copy/restore. This is not a lock against external software changing selected folders; do not restore while an external game/cloud-sync process writes there. Copies are checksummed, not authenticated packages from a trusted publisher. There is no automatic cloud upload/sync or game-specific save discovery in this package.

**Settings → Keep display awake during games** defaults off for old/new settings. It holds one process-owned IOPM idle-display assertion only for observed `.game` entries, using the existing process matcher. Launchers, preparation and timed-out starts do not count. The assertion is released on last-game disappearance (including crash/Stop), toggle-off, shutdown and process death. Each GUI/shortcut owner manages its own assertion. Steam shortcut owners wait for the requested game's bounded startup/observed exit rather than exiting after a URI handoff. Manual lock, lid/thermal sleep and global power policies are not overridden. This is not an FPS boost.

No MacadeKit source was copied or linked. The existing ExeRunner GPL-3.0-or-later license applies to the new implementation; competitor interfaces, text and artwork were not copied. MacadeKit's Apache-2.0 LICENSE and NOTICE were read; any future code reuse needs the applicable notices/modification attribution. Its root license does not relicense Wine, Legendary/gogdl, Apple software or per-folder exceptions. - `bash scripts/test.sh save-archive-test.sh --native`: 68 checks, synthetic saves only; includes actual IOPM assertion creation/removal, modified/corrupt snapshots, required safety backup, no-delete overlay, partial failure recovery, path/empty-directory aliases, shutdown drain and bounded game observation.
- Existing core: 70 passed. Existing shutdown control passed (own process stopped, foreign prefix preserved).
- Localization: complete English/Russian coverage, no untranslated/outside-t() strings.
- Universal build via `script/build_and_run.sh --build-only`, strict signature verification and synthetic save-view export are recorded with the handoff. Native UI export proves layout only, not an end-to-end owner restore or real Steam-session acceptance.

No real save restore, physical device test, engine replacement or installed-app deployment is part of these checks.

## Product direction and separate risks

MaPC overlaps substantially in launching Windows games, Wine integration, renderers and per-game settings. ExeRunner's implemented broader Windows-program/component/environment/device workflows provide a credible direction; uniqueness and demand are not established by absence from a competitor webpage. General compatibility cannot be promised for every Windows application, driver or USB protocol.

[MaPC's pricing](https://mapc.games/#support) keeps game launching free and sells optional one-time supporter conveniences. Its site identifies Steale LLC and its source README claims the MaPC trademark. These statements do not establish company registry status, trademark registration or a patent. Those statuses remain unverified. Company registration creates an entity; a trademark concerns a source-identifying brand; a patent concerns an invention, not simply an app name. [USPTO distinguishes these categories](https://www.uspto.gov/trademarks/basics/trademark-process).

[Apple's current support statement](https://support.apple.com/en-us/102527) says general Rosetta availability ends after macOS 27, with macOS 28 retaining functionality only for certain older, unmaintained games relying on Intel frameworks. Apple has not confirmed that ExeRunner's Wine stack qualifies. The installed runtime's host Wine is x86_64; on Apple Silicon, Windows x86/x64 instruction translation still depends on Rosetta, separately from Wine's Windows API implementation and graphics translation. A universal SwiftUI executable fixes only the shell. Per-environment engine selection is useful infrastructure, but does not supply a replacement translator.

[CodeWeavers' ARM64 Preview report (31/07/2026)](https://www.codeweavers.com/blog/mjohnson/2026/7/31/crossover-preview-the-right-to-bear-arm64-on-mac) documents native ARM64 Wine with their macOS FEX adaptation and ARM64EC support. That report describes testing-only limitations: D3DMetal absent, launcher compatibility problems, new ARM64 bottles required, native pieces requiring macOS 26.5+. Its roadmap is not ExeRunner acceptance or proof of later fixes. Next technical checkpoint: a separately pinned ARM64 Wine/FEX candidate, licenses/build provenance and synthetic PE32/PE32+/exception/graphics tests in new disposable environments. Do not convert existing game prefixes or replace the checked engine for that investigation.
